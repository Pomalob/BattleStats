# StatsBattle — заметки для Claude Code

FastAPI + PostgreSQL, разбор реплеев «Мира Танков». Общее описание — в [README.md](README.md).

## Команды

```bash
pytest                                  # весь набор тестов
uvicorn src.app:app --reload            # локальный запуск (нужен DATABASE_URL)
docker compose up --build               # приложение + локальный Postgres
```

## Устройство

- `src/config.py` читает окружение **на импорте** и падает при старте, если в проде
  нет нормального `SECRET_KEY`. Тесты, которым нужно другое окружение, перезагружают модуль
  через `importlib.reload` и возвращают его обратно фикстурой.
- `src/app.py` импортирует функции базы по именам, поэтому тесты подменяют их
  через `monkeypatch.setattr(app_module, ...)` — см. `tests/conftest.py`.
- Соединения берутся из пула (`database.get_conn()`), который коммитит на выходе
  и возвращает соединение обратно. Не открывай `psycopg2.connect` напрямую.
- Парсер работает с байтами (`parse_replay_bytes`); загруженные файлы никогда
  не попадают на диск.

## Правила

- Ники игроков, названия карт и танков приходят из файлов реплеев — в HTML только
  через `esc()`. Внутри страниц нет инлайновых `onclick` с подстановкой данных,
  используется делегирование по `data-*`.
- Бои общие между пользователями, а владение — через `user_battles`. Удаление
  отвязывает бой от пользователя и удаляет строку, только когда владельцев не осталось.
- Скрытие игрока (`hidden_players`) — это фильтр в аналитике конкретного пользователя,
  а не удаление данных. Не заменяй его на `DELETE`.
- Всё, что приходит от клиента в `/api/battles/save`, пересобирается в `_clean_battle`:
  в SQL попадают только известные поля с приведёнными типами.
- Изменения схемы — идемпотентным `_DDL` плюс `_run_migration` для того,
  что нельзя выразить через `CREATE TABLE IF NOT EXISTS`.
