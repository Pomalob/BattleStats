# StatsBattle

**Живая версия: https://battlestats.onrender.com** (из России — только через VPN; переезд на Timeweb Cloud — ниже)

Разбор реплеев «Мира Танков» (`.mtreplay`) и статистика по своему взводу или клану.
Загружаешь пачку реплеев — получаешь таблицы по урону, ассисту, заблокированному,
фрагам и точности, а нужные бои сохраняешь в базу и смотришь накопленную аналитику.

Стек: FastAPI + PostgreSQL, фронтенд — три статические страницы без сборки.

## Возможности

- **Быстрый чек** (`/`) — перетащил реплеи, сразу увидел матрицу «игроки × бои» по пяти метрикам.
  Ничего не сохраняется, пока не нажмёшь «Сохранить в базу».
- **Аналитика** (`/analytics`) — накопленная статистика: игроки, игрок × танк, карты, список боёв.
  Переключатель «Все бои / Мои бои» и порог «Мин. боёв»: на нескольких сотнях случайных боёв
  подавляющее большинство ников встречается один раз и топ по среднему урону забивают
  случайные союзники. По умолчанию показываются те, у кого от трёх боёв.
- **Дедупликация** — один и тот же бой, выгруженный разными людьми, попадает в базу один раз
  (ключ — хеш от карты и пар «ник: урон»). При сохранении видно, что именно произошло:
  сколько боёв новых, сколько добавилось в твою историю от других игроков, сколько уже было.
- **Незавершённые реплеи** (запись оборвалась до конца боя) показываются отдельным уведомлением
  и не сохраняются: в них нет результатов, и в статистике они дали бы ничью с нулями у всех.
- **Скрытие игроков** — случайных союзников можно убрать из своей аналитики, не удаляя данные боя.
- **Аккаунты** — регистрация, вход, JWT в `localStorage`; бои привязаны к тому, кто их выгрузил.
- **Массовая загрузка** — папку реплеев целиком можно перетащить как есть: страница режет её
  на пачки и шлёт по частям, показывая прогресс. Один реплей весит около мегабайта.

## Быстрый старт

### Через docker compose (нужен только Docker)

```bash
docker compose up --build
```

Приложение поднимется на http://localhost:8000 вместе с локальным Postgres.

### Локально, без Docker

Понадобится Python 3.12 и доступный Postgres (например, бесплатная база на [Neon](https://neon.tech)).

```bash
python -m venv .venv && .venv/Scripts/activate      # Linux/macOS: source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env                                 # и заполнить DATABASE_URL
export DATABASE_URL="postgresql://..."               # Windows: $env:DATABASE_URL="..."
uvicorn src.app:app --reload
```

Схема базы создаётся сама при старте — миграции запускать не нужно.

### Тесты

```bash
pytest
```

128 тестов без базы: парсер реплеев, аутентификация, конфигурация, разбор `DATABASE_URL`
и все эндпоинты API поверх подменённого слоя базы.

Ещё 21 тест проверяет агрегирующий SQL и выгрузку на настоящем Postgres и пропускается,
если не задан `TEST_DATABASE_URL`. Поднять базу можно через compose:

```bash
docker compose up -d db
TEST_DATABASE_URL=postgresql://battlestats:battlestats@localhost:5432/battlestats pytest
```

Указанная база полностью очищается между тестами — не давай туда боевой URL.

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Что делает |
|---|---|---|---|
| `DATABASE_URL` | да | — | Строка подключения к Postgres. `postgres://` чинится сам, для внешних хостов добавляется `sslmode=require` |
| `SECRET_KEY` | в проде | dev-заглушка | Подпись JWT. Минимум 32 символа, иначе прод не стартует |
| `ENV` | нет | `development` | `production` включает строгие проверки `SECRET_KEY` |
| `TOKEN_TTL_DAYS` | нет | `30` | Срок жизни сессии |
| `MAX_FILES_PER_UPLOAD` | нет | `200` | Лимит файлов за одну загрузку |
| `MAX_FILE_SIZE` | нет | `10485760` | Лимит на один файл, байт |
| `MAX_UPLOAD_SIZE` | нет | `157286400` | Лимит на всю загрузку, байт |
| `DB_POOL_MIN` / `DB_POOL_MAX` | нет | `1` / `5` | Размер пула соединений |
| `LOGIN_MAX_ATTEMPTS` | нет | `10` | Неудачных входов до блокировки пары IP+логин |
| `LOGIN_LOCKOUT_SECONDS` | нет | `300` | Длительность блокировки |

Сгенерировать ключ:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

## Деплой на Timeweb Cloud (доступно из России без VPN)

Render и Neon стоят на зарубежной инфраструктуре и из России открываются через раз.
[Timeweb Cloud](https://timeweb.cloud) — российский провайдер: App Platform собирает
[`Dockerfile`](Dockerfile) прямо из GitHub и передеплоит на каждый коммит, отдельного
конфига не нужно. Порт берётся из `EXPOSE 8000`.

1. **Приватная сеть.** В панели → **Сети** создай приватную сеть в регионе Москва.
   Приложение и база будут ходить друг к другу по ней, без публичного IP.
2. **База.** **Облачные базы данных → PostgreSQL** (версия 16+), тот же регион, та же приватная
   сеть. Публичный IP не нужен. Создай базу и пользователя, возьми приватный IP кластера и собери
   `postgresql://<user>:<pass>@<приватный IP>:5432/<db>?sslmode=disable`.
   - `sslmode=disable` обязателен: для любого не-localhost адреса приложение само требует TLS,
     а по приватному IP кластер TLS не отдаёт. Трафик при этом не выходит из приватной сети.
   - Базу держи в Timeweb, а не на Neon: из российского дата-центра до Neon может не достучаться.
3. **Приложение.** **App Platform → Создать → Docker → Dockerfile**, подключи GitHub
   и репозиторий `BattleStats`, ветка `master`, «Сборка по последнему коммиту» — включена.
   Регион — тот же, тариф — минимальный.
4. **Переменные** (шаг «Переменные»):
   - `DATABASE_URL` — строка из шага 2;
   - `SECRET_KEY` — `python -c "import secrets; print(secrets.token_urlsafe(48))"`;
   - `ENV=production`.
5. **Расширенные настройки:**
   - приватная сеть — та, что из шага 1 (потом поменять нельзя);
   - путь проверки состояния — `/healthz`. Он отвечает `503`, если нет базы, поэтому
     деплой со сломанным `DATABASE_URL` откатится на прежнюю версию, а не уронит сайт.
6. **Деплой.** Сайт откроется на бесплатном техническом домене с HTTPS. В логе деплоя должно быть
   `[DB] init OK`; если там `[DB] init failed` — проверь `DATABASE_URL`.
7. **Данные** — перенеси из Neon, см. «Перенос данных» ниже. `SECRET_KEY` новый,
   поэтому всем придётся войти заново; аккаунты и пароли переедут вместе с базой.

## Деплой на Render + Neon

1. **База.** На [neon.tech](https://neon.tech) создай проект (регион `eu-central-1`) и скопируй
   connection string вида `postgresql://user:pass@ep-....neon.tech/dbname`.
2. **Приложение.** На [render.com](https://render.com) → **New → Blueprint**, укажи этот репозиторий.
   Render прочитает [`render.yaml`](render.yaml), создаст free web service и сам сгенерирует `SECRET_KEY`.
3. В настройках сервиса задай `DATABASE_URL` — это единственная переменная, которую Render не знает.
4. Деплой. Health check ходит в `/healthz`; если он красный, смотри логи — там будет `[DB] init failed`
   с причиной (чаще всего опечатка в connection string).

Free-тариф Render усыпляет сервис после 15 минут простоя, первый запрос после этого
занимает около 30 секунд. Neon тоже засыпает, но просыпается за доли секунды.

Проект также совместим с Railway и Heroku — там используется [`Procfile`](Procfile).

### Перенос данных со старого хостинга

Пока старая база жива:

```bash
pg_dump "<старый DATABASE_URL>" --no-owner --no-privileges -f battlestats.sql
psql "<новый DATABASE_URL>" -f battlestats.sql
```

Начисто почистить базу (аккаунты сохраняются, если не передать `--users`):

```bash
DATABASE_URL="postgresql://..." python scripts/clear_db.py
```

## API

Всё, кроме страниц и `/healthz`, требует заголовок `Authorization: Bearer <token>`.

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/auth/register` | Регистрация, возвращает токен |
| `POST` | `/api/auth/login` | Вход, возвращает токен |
| `GET` | `/api/auth/me` | Текущий пользователь |
| `POST` | `/api/upload` | Разбор `.mtreplay` (multipart). Ничего не сохраняет |
| `POST` | `/api/battles/save` | Сохранение выбранных боёв в базу |
| `GET` | `/api/battles?mine=` | Список боёв |
| `DELETE` | `/api/battles/{id}` | Убрать бой из своей истории |
| `GET` | `/api/analytics/summary?mine=` | Агрегаты: итоги, игроки, карты, танки |
| `GET` | `/api/export?mine=&date_from=&date_to=` | Все бои со всеми полями по порядку дат, JSON-файлом |
| `GET` | `/api/export/table/battles?mine=&date_from=&date_to=` | Плоская таблица боёв для BI: `{"columns": [...], "total": N, "rows": [...]}` |
| `GET` | `/api/export/table/players?mine=&date_from=&date_to=` | Плоская таблица «игрок в бою», связь с боем по `battle_id` |
| `GET` | `/api/players/hidden` | Скрытые игроки |
| `POST` | `/api/players/hidden` | Скрыть игрока (`{"name": "..."}`) |
| `DELETE` | `/api/players/hidden/{name}` | Вернуть игрока |
| `GET` | `/healthz` | Health check: `200` если база отвечает, иначе `503` |

Интерактивная схема — `/docs`.

### Выгрузка в JSON

На странице аналитики есть кнопка «Скачать JSON» — она выгружает бои текущего охвата.
То же самое без браузера:

```bash
TOKEN=$(curl -s -X POST https://battlestats.onrender.com/api/auth/login \
  -H 'Content-Type: application/json' -d '{"username":"...","password":"..."}' | jq -r .token)
curl --compressed -H "Authorization: Bearer $TOKEN" \
  "https://battlestats.onrender.com/api/export?mine=true&date_from=2026-09-01" -o battlestats.json
```

- `mine` — `true` (по умолчанию) только свои бои, `false` — все.
- `date_from`, `date_to` — `ГГГГ-ММ-ДД`, включительно. Оба необязательны.
- Бои идут от старых к новым. У каждого боя: `details` (сервер, режим, длительность,
  причина окончания, HP команд, `arenaUniqueID`), `recorder` (кто записал реплей — только для
  своих загрузок) и `players` — основные колонки плюс `details` с полной статистикой из реплея:
  `accountDBID`, клан, взвод (`prebattleID`), урон с разбивкой, ассист по видам, стрельба,
  полученные попадания, засвет, оглушение, смерть (`killerID` ссылается на `details.vehicleID`).
  Названия полей — как в самом реплее.
- Опыт, кредиты, медали, боевой пропуск и поля особых режимов не выгружаются.
- Бои, сохранённые до появления расширенных полей, приходят с `details: null` — их число в
  `battles_without_details`. Повторная загрузка тех же реплеев дописывает детали в уже сохранённые бои.

Ответ сжимается gzip: 750 боёв — около 24 МБ JSON и 2 МБ по сети.

### Из JSON в таблицу

[`scripts/export_to_table.py`](scripts/export_to_table.py) не зависит от остального проекта —
его можно скопировать отдельно на любой компьютер с Python 3.10+.

```bash
python -m pip install openpyxl                                  # только для .xlsx, в тот же python, которым запускаешь
python export_to_table.py                                       # самый свежий .json из папки battlestats в Nextcloud
python export_to_table.py -r battlestats_mine_20261105.json     # конкретный файл из этой папки
python export_to_table.py battlestats.json                      # локальный файл -> battlestats.xlsx
python export_to_table.py battlestats.json -o stats.csv         # -> stats_battles.csv, stats_players.csv
python export_to_table.py battlestats.json --bi                 # -> плоские CSV для Форсайта, см. ниже
```

Без пути к файлу JSON берётся из Nextcloud по WebDAV, нужны переменные окружения:

| Переменная | Что это |
|---|---|
| `NEXTCLOUD_URL` | адрес облака, например `https://cloud.example.ru` |
| `NEXTCLOUD_USER` | логин |
| `NEXTCLOUD_PASSWORD` | пароль приложения (Настройки → Безопасность → «Создать пароль приложения»); если не задан, скрипт спросит его |
| `NEXTCLOUD_FOLDER` | папка с выгрузками, по умолчанию `battlestats` |

- Таблица сохраняется в текущую папку под именем JSON-файла (`battlestats_mine_….xlsx`), `-o` меняет путь.
- Если вход через LDAP/AD и внутренний ID не совпадает с логином, скрипт узнаёт ID сам.
- `--no-verify-tls` — для облака с корпоративным самоподписанным сертификатом.
- Кроме стандартной библиотеки ничего не нужно; `openpyxl` — только для `.xlsx`.

- Лист **«Бои»** — строка на бой: дата, карта, результат, длительность, режим, сервер, кто записал.
- Лист **«Игроки»** — строка на игрока в бою (750 боёв ≈ 13 000 строк): поля боя для фильтра,
  основные цифры с русскими заголовками, точность и процент пробитий, флаг «Союзник»,
  дальше все расширенные поля реплея под их родными именами.
- Без `openpyxl` скрипт сам переключится на CSV (`;`, UTF-8 с BOM — Excel открывает как есть).
- `arenaUniqueID` пишется текстом: в нём 17 цифр, а Excel хранит только 15 и округлил бы его.

### Форсайт. Аналитическая платформа и куб

[`integrations/foresight/BattleStats.fore`](integrations/foresight/BattleStats.fore) — модуль на Fore
с двумя процедурами:

- **`Setup`** (один раз) создаёт таблицы, справочники и стандартный куб `BS_CUBE`;
- **`Main`** (при каждом обновлении) перезаливает `BS_BATTLES` и `BS_PLAYERS` и пересобирает
  справочники измерений. Куб читает таблицы напрямую, отдельно обновлять его не нужно.

Источник для `Main` задаёт константа `SOURCE`:

- `"site"` — сайт по REST, `/api/export/table/battles` и `/api/export/table/players`;
- `"csv"` — два файла из скрипта: `python export_to_table.py battlestats.json --bi` →
  `battlestats_bi_battles.csv` и `battlestats_bi_players.csv`. Колонки те же, что у сайта, разделитель
  `;`, UTF-8 без BOM. Обычные CSV и `.xlsx` с русскими заголовками для загрузки не подходят — они для чтения.

**Куб `BS_CUBE`** строится на `BS_PLAYERS`, одна строка — один игрок в одном бою.

| Измерения | Факты (сумма по строкам) | Вычисляемые факты |
|---|---|---|
| День, Карта, Танк, Игрок, Исход для игрока (победа / поражение / ничья), Сторона (союзники / противники записавшего) | Бои, Победы, Урон, Ассист, Заблокировано, Получено урона, Фраги, Выжил, Выстрелы, Попадания, Пробития, Засвет | Средний урон, Средний ассист, Процент побед, Точность %, Выживаемость % |

`result` — исход для того, кто записал реплей; для куба взяты `outcome`/`win` — исход для самого
игрока (его команда против `winner_team`), иначе у противников победа считалась бы поражением.

Как запустить:

1. Создай модуль, вставь код, в «Ссылках» модуля подключи сборки
   Collections, Cubes, Db, Dimensions, Dt, IO, Metabase, Net.
2. В настройках модуля впиши `DATABASE_ID` — идентификатор объекта «База данных» репозитория,
   где будут таблицы, при желании `FOLDER_ID` (папка для объектов). Для сайта — логин и пароль,
   `MINE`, `DATE_FROM`; для CSV — пути к файлам и `SOURCE = "csv"`.
3. Для сайта: попроси администратора добавить `battlestats.relaxdev.ru` в белый список хостов
   репозитория (`HostWhiteList`) — без этого REST-запросы отклоняются.
4. Запусти `Setup`, потом `Main`. Повторный `Setup` пропускает уже созданные объекты.
5. Для автообновления — Планировщик задач, задача выполнения модуля, процедура `Main`.

Колонки таблиц описаны в функциях `BattleColumns`/`PlayerColumns` модуля; поле таблицы сопоставляется
с колонкой источника по имени без учёта регистра (`DAMAGE_DEALT` ← `damage_dealt`). Тест
`tests/test_foresight_module.py` следит, чтобы колонки модуля, сайта и `--bi` совпадали, а факты и
измерения куба ссылались на существующие поля. Сам модуль в Форсайте здесь не запускался — он написан
по примерам из справки платформы, и при первой компиляции возможны мелкие правки.

## Формат .mtreplay

`magic (4 байта) | число блоков (4) | размер блока (4) | JSON | размер блока (4) | JSON`

Первый блок — метаданные боя (карта, дата, состав), второй — результаты
(`[итоги, игроки, фраги]`). Незавершённые реплеи содержат только первый блок:
такой бой разбирается как ничья с составом, но без статистики.
